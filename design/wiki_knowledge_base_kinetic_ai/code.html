This document outlines the product requirements and technical specifications for the upcoming V2 release of the Kinetic AI core architecture. Our primary goal is to shift from a monolithic inference engine to a distributed, highly scalable micro-agent framework.

1. Executive Summary link

Currently, our inference pipeline struggles with latency when context windows exceed 32k tokens. By moving to a distributed architecture, we anticipate a 40% reduction in median response time and improved fault tolerance across active workspaces.

The current system is okay but it gets really slow when a lot of users try to run big complex queries at the exact same time, which makes people annoyed and hurts our retention numbers.

2. Technical Requirements

The new architecture must conform to the following specifications, as discussed with @Marcus Thorne and the DevOps team:

  • Latency: p95 latency under 800ms for standard text completions.
  • Scalability: Auto-scaling workers based on queue depth metrics.
  • Storage: Transition from Postgres to specialized Vector DB for context retrieval.
